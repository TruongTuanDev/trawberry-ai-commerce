# i18n

## Locale switcher flags

- The shared language switcher now renders local SVG flag icons for `RU`, `EN`, and `VI` instead of text-like pseudo-icons.
- Role policy is unchanged:
  - public/customer: `RU/EN`
  - seller: `RU/EN/VI`
  - admin: English only, no switcher
- Locale metadata now maps to stable local flag keys, while the dropdown keeps the existing live-switch and persistence behavior.

## Role policy

- Admin:
  - supported locales: `en`
  - default locale: `en`
  - no language switcher
- Seller:
  - supported locales: `ru`, `en`, `vi`
  - default locale: `ru`
  - language switcher visible in Seller Center
- Public / customer:
  - supported locales: `ru`, `en`
  - default locale: `ru`
  - language switcher visible in public surfaces

## Resolution order

1. logged-in user `preferredLocale`
2. locale cookie
3. role default

Current phase intentionally does not let browser language override the public default Russian fallback.

- shell navigation
- products list and product status/action labels
- orders tabs and order actions
- payment review queue and payment detail

Seller payment settings and product filtering now also live-switch correctly in `ru`, `en`, and `vi` without a page reload:

- `/seller/payment-settings`
- `/seller/products` filter/search toolbar
- seller shop switcher chrome
- seller product editor visibility metadata form

Seller direct routes now hydrate without relying on a preselected `currentShopId`:

- `/seller/orders/[id]`
- `/seller/payments/[orderId]`
- `/seller/products/[id]`
- `/seller/products/[id]/images`
- `/seller/orders`
- `/seller/payments`

The frontend resolves the needed shop context from seller-accessible detail APIs, then syncs the workspace store after the detail payload loads.

Seller order detail is now fully localized for `ru`, `en`, and `vi`:

- `/seller/orders/[id]`
- seller fulfillment summary labels
- seller manual Yandex handoff form labels
- shipping-label entry actions inside order detail
- seller delivery status and next-action chrome
- seller order-detail business E2E now uses raw `data-raw-status` / `data-bucket` contracts instead of translated text

Seller remaining operations are now localized for `ru`, `en`, and `vi` across the older operational screens that were still leaking mixed-language copy:

- `/seller/support-cases`
- `/seller/onboarding`
- `/seller/pending`
- `/seller/import/wildberries`
- `/seller/import/wildberries-api`
- `/seller/messages`
- seller login/register seller-only chrome and placeholders
- seller notification metadata/error fallbacks

Specific cleanup points:

- support-case status, issue type, and sender-role labels now resolve through seller dictionaries instead of raw backend enum values
- onboarding and pending pages now translate approval state, legal type, document type, document status, and seller next-step UI chrome
- Wildberries Excel and API sync pages now avoid hard-coded English placeholders such as `Row`, `N/A`, `Yes/No`, `MOCK`, `NOT_VERIFIED`, and result-section headings
- seller message list status chips now localize while business tests continue using stable selectors instead of translated copy
- frontend runtime no longer depends on `next/font/google`, so Docker builds do not fail on Google Fonts network fetches

Buyer locale policy remains unchanged for reviews:

- supported locales: `ru`, `en`

Review photo upload rules:

- up to `5` photos per review
- `JPG`, `PNG`, `WEBP` only
- `5 MB` max per image
- no video upload yet
- hidden reviews hide their public photos too

Business regressions should not assert translated copy. Customer E2E contracts now prefer:

- `data-testid`
- raw `data-status`
- route or visibility outcomes

## Customer cleanup audit

- Buyer/customer UI remains `ru` and `en` only.
- Customer notifications shell no longer contains Vietnamese hard-coded text.
- Customer returns/refunds no longer depend on browser-native file input labels; the UI now uses a localized custom trigger and filename state.
- Customer receipt and support sections now subscribe to live customer locale state instead of mixing static English labels into RU sessions.

## Error and toast localization

Frontend maps stable error codes instead of translating backend free-text strings. Current shared mappings include:

- `CUSTOMER_ADDRESS_REQUIRED`
- `CUSTOMER_ADDRESS_NOT_YANDEX_READY`
- `SHOP_PAYMENT_METHOD_NOT_SUPPORTED`
- `UNAUTHORIZED`
- `FORBIDDEN`
- `VALIDATION_ERROR`
- `OUT_OF_STOCK`
- `PRODUCT_NOT_AVAILABLE`

## Remaining gaps

- seller finance, returns, and some older AI/workbench screens still contain legacy hard-coded copy outside the current migration scope
- some older shared flows still need contract hardening from localized text assertions to `data-testid` or raw status assertions

## Admin operations status

- seller approval list and seller onboarding detail
- seller fee supervision
- fulfillment and deliveries supervision
- payments supervision
- returns / refunds / disputes

Admin-specific cleanup rules now applied:

- admin confirm dialogs, loading labels, and success toasts no longer leak Vietnamese copy
- garbled or mixed-language text was removed from admin operational chrome
- admin business regressions were tightened toward stable selectors in the touched specs where flaky text assertions or teardown behavior were the real issue

## Locale switcher redesign

- seller and buyer/customer surfaces now use one shared locale switcher component with a central locale metadata map
- each dropdown item shows flag, short code, native language name, and active check state
- seller switcher supports `RU / EN / VI`
- public and customer switchers support `RU / EN` only
- live switching stays client-side and immediate, while preferred locale persistence still uses the existing cookie plus `/api/users/locale` flow

## Marketplace cleanup addendum

- compatibility staff login on `/login` now replays the role-specific login endpoint after role detection so seller/admin locale-protected routes keep working after refresh
- customer-facing canonical locale switcher test id is now single-instance on public/auth surfaces; secondary customer/account and mobile switchers use distinct ids
- seller locale menu now renders above seller operations content, preventing click interception on product and order workspaces
- validated locale regressions:
  - public/customer `RU/EN` only, default `RU`
  - seller `RU/EN/VI`, live switching retained
  - admin remains `EN` only with no switcher
